Buena pista para diagnosticar: si el token es el mismo y solo cambia la IP de origen, casi seguro no es un problema de autenticación sino de autorización por origen — algo en el camino está aceptando la conexión TCP pero rechazando la request a nivel de aplicación. Eso es justamente lo que indica un 403 (a diferencia de un timeout o "connection refused", que apuntaría a firewall/red).

Causas más probables (de más a menos común)

1. Allowlist de IP/subred en el propio gateway
Muchos gateways OpenAI-compatible self-hosted (LiteLLM, LocalAI, text-generation-webui, proxies caseros tipo FastAPI/Starlette) traen o permiten configurar una lista de IPs/hosts confiables (trusted_hosts, allowed_ips, TrustedHostMiddleware, etc.). Si OmniRoute quedó configurado por defecto para aceptar solo 127.0.0.1 o la IP propia de la máquina, cualquier IP distinta —aunque el Bearer sea válido— cae en un 403 explícito antes de llegar a la lógica de auth por token.

2. Reverse proxy delante del gateway
Si hay nginx/Caddy/Traefik enfrente de OmniRoute, es común tener reglas tipo allow 192.168.0.11; deny all; puestas ahí (no en el gateway) para "seguridad rápida". Desde el punto de vista del cliente el síntoma es idéntico.

3. Validación del header Host
Algunos frameworks rechazan requests cuyo header Host no coincide con un valor esperado (defensa contra Host header injection). Si PowerShell y Python arman el header Host de forma distinta (poco probable pero posible según cómo armaste la URL), podría disparar esto. Se descarta rápido comparando con curl -v.

4. Bearer token "pinned" a IP de origen
Algunos gateways (sobre todo los pensados para exponer LLMs locales) implementan una capa extra donde el token queda asociado a la primera IP que lo usó, como mitigación anti-leak. Si ese es el caso, el 403 vendría acompañado de un mensaje específico en el body o en logs del server.

Lo que casi seguro NO es: CORS. CORS lo aplica el navegador, no urllib ni requests en Python — un script no respeta ni dispara preflight, así que si el error fuera CORS, ni siquiera verías un 403 sino que la request pasaría igual (CORS es un chequeo del lado cliente/navegador, no del servidor bloqueando).

Cómo diagnosticar rápido
Descartar firewall/red primero:
bash
   nc -vz 192.168.0.11 20128

Si conecta, el problema es 100% de aplicación, no de red/firewall de Windows.

Comparar requests exactas con curl en ambas máquinas (mismo binario, mismos headers):
bash
   curl -v -X POST http://192.168.0.11:20128/v1/chat/completions \
     -H "Authorization: Bearer ***" \
     -H "Content-Type: application/json" \
     -d '{"model":"oc/big-pickle","messages":[{"role":"user","content":"hola"}]}'

Corré esto desde la Mac y desde la misma Windows machine, y compará headers de respuesta y el body del 403 (muchos gateways devuelven un mensaje como "IP not allowed" o "host not trusted" en el JSON de error, que te dice exactamente cuál es la regla).

Revisar logs de OmniRoute en el momento del request rechazado — ahí debería quedar registrada la razón exacta del 403 (esto acorta mucho la búsqueda).
Cómo autorizar el acceso desde la LAN
Buscá en la config de OmniRoute algo tipo allowed_hosts, trusted_ips, cors_origins, bind_address y agregá la subred local, ej. 192.168.0.0/24, o al menos la IP de la Mac.
Si hay reverse proxy delante, ajustá ahí las reglas allow/deny.
Verificá también el firewall de Windows (perfil de red y regla de entrada para el puerto 20128): asegurate que el scope remoto sea "Cualquier IP" o "Subred local" y no solo "Este equipo" — aunque esto normalmente da timeout y no 403, conviene descartarlo si tocás algo y sigue fallando.
Ya que vas a abrir esto a la LAN: tené en cuenta que es HTTP plano, así que el Bearer viaja sin cifrar por la red local. Si otros dispositivos comparten esa red (Wi-Fi con vecinos, etc.), conviene poner el gateway detrás de TLS aunque sea con un certificado autofirmado, o al menos restringir por IP como estás pensando hacer.

Si me pasás el mensaje de error exacto del body del 403 (no solo el código), puedo ayudarte a identificar con más precisión cuál de las cuatro causas es.
